Suggested plan for two days

Phase 1: Skeleton (first hours)

Set up the venv, run the provided FastAPI starter, and confirm /spyrja_px_api works with cURL.
Confirm Ollama is running with hagstofa-ai:latest.
Do one hardcoded end-to-end path (e.g. population in a given year) before generalising.

Phase 2: Table selection

Load the catalog (HELSTU_TOFLUR or hagstofa_catalog.json) into RAM at startup using lifespan.
Normalise text (NFKD, strip combining marks, lowercase, explicit þ→th and æ→ae mapping), then score tables by keyword and title overlap.
Consider a hybrid: keyword scoring to shortlist the top 3 to 5 tables, then optionally let the LLM pick among them. It handles synonyms better than pure keyword matching.

Phase 3: Dimension filtering (the hard part)

GET the table metadata, then extract years, regions, sex, and other dimensions from the question and map them to valid codes.
Validate every code against the metadata before POSTing. If a selection is invalid or ambiguous, ask a clarifying question rather than guessing.
Apply size limits on broad queries (e.g. cap the number of cells, default to the latest year).

Phase 4: Answer generation

Pass the LLM a compact structure: question, selected dimensions, values, units, source table and URL.
Use low temperature (0.2 as in the slides).
Add a post-check that the numbers in the answer appear in the retrieved data.
Always append the source and selected dimensions programmatically, not via the LLM.

Phase 5: Frontend and extras

Simple web UI with loading and error states, and answers showing values, units and source.
Track 2 specifically requires multiple questions in one API call and concurrency, so plan for this early. Use asyncio with httpx for the PX-API calls, and remember the slides note that threading.Lock() only serialises Ollama calls inside one process.
